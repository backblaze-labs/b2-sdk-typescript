## [0.6.1] - 2026-11-27

### Changed

- Standardized release preparation with Changie fragments, release milestones, security triage, and a maintainer tag-signature check that initially warns until key enrollment is complete. Package versioning remains with pnpm/npm, and publishing retains OIDC trusted publishing and provenance.

### Fixed

- Native create-key, create-bucket, copy-file, and hide-file requests now surface connection failures and HTTP 408/5xx responses without automatic replay. Expired-token reauthorization, HTTP 429 backoff, and read/download retries remain enabled. Check the operation's result before manually retrying a mutation.
- Parallel downloads retry interrupted range response bodies using the client's retry settings, without emitting partial range bytes.
- The presigned download example now returns a 400 response for malformed URL encoding instead of terminating the server.
- Sync keep-days requires a finite, non-negative keepDays value; explicit 0 remains valid. Parallel downloads require positive integer concurrency and positive range sizes without retaining abort listeners on rejection. Copies preserve source fileInfo unless a replacement is supplied, including when only contentType is changed.
- B2-to-B2 sync uses multipart copy above the 5 GB single-copy limit. Modtime sync preserves and compares source modification times instead of uploading unchanged local files again. Orphan deletion removes completed versions and hide markers in unlocked buckets while preserving unfinished uploads.
- Streams that fit in one part finalize through the single-request upload path, forwarding only supported streaming options. At exactly one part, the provisional large file is cancelled and the retained bytes are uploaded again as a single file. Failed parts reject completion and cancel the unfinished large file even when the writer remains open.
- Retry delays remove abort listeners when they settle, preventing listeners from accumulating on a reused signal.
- Bucket.copyFile now defaults to the bucket associated with the handle when destinationBucketId is omitted.
- The backup CLI example associates its local manifest with the bucket and prefix, preserves backups across API endpoint changes, and verifies copied or legacy remote manifests against the destination before skipping files.
- Parallel ranged downloads track request-transport and body-reset retries with independent budgets, so a retryable failure of one kind no longer consumes the other kind's retry allowance.
- Reject multipart uploads, copies, and streams that exceed B2's 10,000-part limit before an invalid part can be sent. Stream close and completion preserve the original part-limit error.
- Part upload URLs are discarded after their large file is finished or successfully cancelled.
- Reject restore paths outside the destination and malformed webhook signature hex; restrict credential cache directories to owner access.
- Bucket lifecycle rule additions and removals retry revision conflicts using a fresh rule set, preserving concurrent updates.
- Download requests with file names resembling upload endpoints retain normal retry behavior.
- The sync CLI exits nonzero when an action fails. Large uploads reject invalid concurrency before reading or starting, and server errors while finishing a large file are treated as ambiguous without automatic cancellation.
- The simulator applies Object Lock retention and legal hold to small uploads and copies, including destination bucket defaults.
- Concurrent replication rule updates retry revision conflicts instead of silently overwriting one another.
- Upload streams preserve retained chunk bytes when callers reuse or overwrite source buffers between writes or reads.
- Single-file write streams honor the client connection-fault retry setting and per-call overrides.
